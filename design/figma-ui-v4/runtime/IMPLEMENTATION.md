# 千绵美学 V4 实际界面交付

2026-10-20。依据已确认的 V4 设计，将店长日常业务应用到 uni-app / Vue 页面。设计样例与正式业务数据分开。

## 已落实

- 首页经营概览、四项快捷服务、会员关怀、最近消费及实际趋势。
- 会员列表、搜索、性别/来源/排序筛选、档案、新增/编辑、次卡、消费记录、按卡流水、短信状态查询。
- 开卡、扣次与其他消费登记；扣次核对、成功结果、余次不足与状态校验；编辑时仅返还原卡的扣减次数。
- 次卡补次、余次调整、停用/启用/作废，消费详情、修改与删除入口。
- 散客登记/编辑、消费查询及日期筛选；员工列表、新增/编辑、状态确认、密码重置弹层。
- 我的、资料/昵称、账号、关于、协议阅读、退出确认与登录页。
- 品牌标识、四栏导航、暖白/紫/金色规范、表单、按钮、次卡与弹层共用组件。

## 交互归属

| 形式 | 业务 |
| --- | --- |
| 底部弹层 | 会员筛选、消费日期、扣次核对、补次、调整余次、密码重置 |
| 居中确认框 | 次卡状态、会员/记录删除、员工停用/启用、退出 |
| 完整页面 | 档案/详情、会员/员工资料、开卡、消费登记/编辑 |

失败时保留输入并展示错误；提交期间阻止重复提交。H5 弹层支持 Tab 循环、Esc 关闭和焦点恢复，危险确认默认聚焦取消。账户与次数校验仍由正式后端最终裁定。

## 接口约束与待定

- 当前会员 page 接口忽略 `memberTab`，因此实际界面暂收起“全部/会员/非会员”三项分类，避免切换后仍返回同一批数据。性别、来源与排序照常使用实际接口。
- 消费 info 只返回原始实体，服务层另取会员资料和卡名，避免直接访问详情无法识别散客、或编辑清空客户备注。
- 首页“首次开卡”使用后台 todayNewMemberCount 的首次开卡人数口径；不等同于新建档案人数。
- 账号角色缺失时展示“门店账号”；平台入口不推定权限。平台运营功能仍单独待定。
- 协议从实际公共 `/app/base/comm/param` 读取，需服务端放行对应 key 并配置正文。短信通知依后端 ready 状态开放，未启用时展示不可用状态。
